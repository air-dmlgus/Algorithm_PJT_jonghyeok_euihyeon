# 냠냠코치 요구사항 정의서

## 범위와 사용자

사용자는 Java 17+ 콘솔에서 회원 정보를 관리하고, 음식 DB의 항목을 선택해 식단을 기록·분석하며 챌린지와 커뮤니티를 이용한다. 로그인하지 않은 사용자는 가입·로그인만 가능하고, 로그인한 사용자는 자신의 데이터만 수정·삭제할 수 있다.

| ID | 분류 | 구현 요구사항 | 완료 기준 | 상태 |
|---|---|---|---|---|
| F201 | 식단 | 날짜·끼니·음식/횟수·메모로 식단 작성 | 하나 이상의 유효 음식으로 ID가 부여됨 | 완료 |
| F202 | 식단 | 본인 식단 전체/ID 상세 조회 | 음식별 횟수와 열량 표시 | 완료 |
| F203 | 식단 | 본인 식단 수정 | ID 확인 후 날짜·끼니·음식·메모 변경 | 완료 |
| F204 | 식단 | 본인 식단 삭제 | 삭제 뒤 조회되지 않음 | 완료 |
| F205 | 식단 | 영양 분석·점수 | 열량·3대 영양소·나트륨·0~100점·조언 | 완료 |
| F206 | 회원 | 회원 가입 | 중복 ID 거부, 프로필 저장 | 완료 |
| F207 | 회원 | 본인 정보 조회 | 프로필·BMI·상태 표시 | 완료 |
| F208 | 회원 | 본인 정보 수정 | 변경 내용 JSON 반영 | 완료 |
| F209 | 회원 | 회원 비활성화 | 로그인 차단, 팔로우 정리 | 완료 |
| F210 | 회원 | 로그인/로그아웃 | 인증 상태별 메뉴 분리 | 완료 |
| F211 | 회원 | 팔로우 추가·취소·목록 | Set으로 중복 금지, 본인 금지 | 완료 |
| F212 | 챌린지 | 정보 등록·조회·삭제 | 기간 역전 거부, 연관 참여 삭제 | 완료 |
| F213 | 챌린지 | 참여·달성도 관리 | 사용자/챌린지 쌍, 0~100% | 완료 |
| F214 | 커뮤니티 | 게시글 CRUD·검색 | 작성자만 변경, 3개 게시판 구분 | 완료 |
| F215 | 커뮤니티 | 댓글 CRUD | 작성자만 변경, 글 삭제 시 연쇄 삭제 | 완료 |
| F216 | AI | 식단 코칭 | AI 인터페이스, 키 없는 규칙 기반 응답 | 완료 |
| F217 | AI | 운동 코칭 | BMI·목표·최근 식단 기반 안전 안내 | 완료 |

## 비기능 요구사항

| ID | 항목 | 수용 기준 |
|---|---|---|
| NF201 | 편의성 | 번호 메뉴, 잘못된 형식 재입력, 한국어 오류 메시지 |
| NF202 | 가용성 | Java 17 이상인 Windows/macOS/Linux 콘솔에서 실행 |
| NF203 | 응답성 | ID 조회는 평균 O(1), 검색/정렬/추천 측정값 출력 |
| NF204 | 정확성 | 영양 합계를 제공량×섭취 횟수로 계산; 샘플 출처 한계 고지 |
| NF205 | 신뢰성 | JSON을 임시 파일에 쓴 뒤 원본과 교체 |
| NF206 | 보안 | 본인 소유 데이터만 변경; 실서비스 비밀번호 해시 필요성 문서화 |

## 추적성

콘솔 화면은 `MenuUI`, 업무 규칙은 각 `*Manager`, 저장은 `DataRepository`, 모델은 `domain`, 알고리즘/입출력은 `util`, AI 교체점은 `ai` 패키지에 있다. 자동 테스트는 KMP 결과·비교 횟수와 병합 정렬 순서·비교 횟수를 검증한다.
